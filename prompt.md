# Build the Yaadi frontend: a prompt for your AI coding assistant

This repo is only the **backend**. To get a working app, paste this whole file into an AI coding tool (Claude Code, Cursor, etc.) inside a new, empty folder. It describes exactly what the backend expects, so the generated frontend can talk to it.

> Tip: if the AI gets something wrong, point it back at the section here that describes it. The sync rules in section 5 matter most.

---

## 1. What you're building

A **personal note-taking web app** for **one person**, installable on phone and laptop as a PWA. It talks to the Yaadi backend (FastAPI on AWS Lambda) described below.

The most important rule is that it's **offline-first**:

- All notes and folders live in the browser (IndexedDB). The UI reads and writes there and never waits for the network.
- Opening, editing, creating and deleting notes all work with no internet connection.
- A background sync engine pushes local changes to the server and pulls changes from other devices when it can.
- Once logged in, going offline must **never** log the user out or block access to their notes.

Features:
- Log in with a single password (no sign-up, no usernames).
- Notes written in **Markdown**, with an editor and a rendered preview.
- Folders, which can be nested, plus tags on notes.
- Instant client-side search across note titles and content.
- Images pasted or dropped into a note get uploaded and shown inline.
- Optional: a "share to Yaadi" target so links shared from a phone become notes (section 8).

## 2. Suggested stack

You can change these, but they fit the job well:

- **React + Vite + TypeScript**
- **vite-plugin-pwa**: manifest, service worker, installable app shell that works offline
- **Dexie.js** (IndexedDB wrapper) + **dexie-react-hooks** (`useLiveQuery`): the local database *is* the app state, so no Redux or similar is needed
- **CodeMirror 6** with `@codemirror/lang-markdown` for the editor
- **markdown-it** for the preview
- **Fuse.js** for fuzzy search
- **react-router**: routes like `/`, `/login`, `/note/:id`, `/folder/:id`
- **Cloudflare Workers** (via `wrangler`) to host the app and proxy the API (section 9; this part is **required**)

## 3. Configuration

One environment variable:

```
VITE_API_BASE_URL=https://api.your-domain.com
```

This is the URL of the **Cloudflare Worker proxy** (section 9), not the raw Lambda URL. The backend rejects any request that didn't come through the Worker.

## 4. The backend API

All request and response bodies are JSON. Every endpoint except `/auth/*` and `/health` needs the header `Authorization: Bearer <access_token>`.

### Data shapes

```ts
interface Note {
  id: string;              // UUID v4, generated by the client (crypto.randomUUID())
  title: string;
  content: string;         // Markdown
  folder_id: string | null;   // null = top level
  tags: string[];
  created_at: string;      // timestamp, see "Timestamps" below
  updated_at: string;
  deleted_at: string | null;  // set = deleted (a "tombstone")
}

interface Folder {
  id: string;              // UUID v4, generated by the client
  name: string;
  parent_folder_id: string | null;  // null = top level
  created_at: string;
  updated_at: string;
  deleted_at: string | null;
}
```

### Timestamps (get this exactly right)

The server compares timestamps **as strings**, so every timestamp must use this exact format: UTC, **microsecond** precision, `+00:00` suffix:

```
2026-10-12T09:30:15.123456+00:00
```

JavaScript's `toISOString()` gives `...15.123Z`, which is the wrong format. Use this helper everywhere:

```ts
function nowIso(): string {
  return new Date().toISOString().replace('Z', '000+00:00');
}
```

### Auth

| Method & path | Body | Returns |
|---|---|---|
| `POST /auth/login` | `{ "password": "..." }` | `{ access_token, refresh_token, token_type: "bearer" }` |
| `POST /auth/refresh` | `{ "refresh_token": "..." }` | a fresh `{ access_token, refresh_token, token_type }` |

- The access token lasts **15 minutes** and the refresh token **30 days**.
- `401` from `/auth/login` means the password is wrong.
- `429` from `/auth/login` means too many wrong attempts, so the IP is locked out for a while. Show "Too many attempts, try again later".

### Sync (the app's main way of talking to the server)

**`POST /sync/push`** sends local changes:

```json
{ "items": [ { "item_type": "note", "data": { ...full Note... } },
             { "item_type": "folder", "data": { ...full Folder... } } ] }
```

Response, with one result per item:

```json
{ "results": [ { "item_type": "note", "id": "...", "status": "accepted" },
               { "item_type": "note", "id": "...", "status": "rejected", "server_item": { ...Note... } } ] }
```

- `accepted`: the server saved it.
- `rejected` **with** `server_item`: the server already has a newer version (last write wins). Replace the local copy with `server_item`.
- `rejected` **without** `server_item`: the item was invalid. Drop it from the queue.
- Always send the **full** item, never a partial one.

**`GET /sync/pull?since=<cursor>`** fetches changes from other devices:

```json
{ "notes": [ ...Note... ], "folders": [ ...Folder... ], "synced_at": "<new cursor>" }
```

- On first sync, use `since=1970-01-01T00:00:00+00:00`.
- Save `synced_at` and send it as `since` next time. **Always use the server's `synced_at`** as the cursor, never the device's own clock.
- The response includes deleted items (with `deleted_at` set). Store them and hide them in the UI.
- The same item can come back more than once. Just upsert it by `id`.

### Attachments (images)

| Method & path | Body | Returns |
|---|---|---|
| `POST /attachments/presign-upload` | `{ "note_id": "...", "content_type": "image/png" }` | `{ upload_url, attachment_id, s3_key }` |
| `GET /attachments/{attachment_id}/download-url` | — | `{ download_url }` |

- Upload the file bytes with a plain `PUT` to `upload_url`, with a `Content-Type` header that **exactly matches** the one you sent above. Don't add an `Authorization` header, because the URL itself is the permission.
- Both URLs expire after **5 minutes**. Cache download URLs for about 4 minutes at most.

### Link preview

`GET /links/preview?url=<encoded url>` returns `{ "title": string | null, "description": string | null }`.

This call is best-effort and never fails. Getting both fields back as `null` just means "no preview".

### Others

- `GET /health` returns `{ "status": "ok" }` and needs no auth. Use it to check whether the server is actually reachable.
- `/notes` and `/folders` also have plain REST endpoints (`GET`, `POST`, `PATCH /{id}`, `DELETE /{id}`). **The app doesn't need them.** Everything goes through local storage + sync.

## 5. The sync engine (the one hard part)

### Local database (Dexie)

```ts
db.version(1).stores({
  notes:     'id, folder_id, updated_at, deleted_at',
  folders:   'id, parent_folder_id',
  syncQueue: '++localId, item_type, item_id',   // pending changes to push
  meta:      'key',                             // e.g. lastSyncedAt
});
```

### Every local change (create, edit, delete)

1. Write it to Dexie right away so the UI updates instantly. Set `updated_at = nowIso()`. New items also get `id = crypto.randomUUID()` and `created_at = nowIso()`.
2. Add `{ item_type, item_id }` to `syncQueue`.
3. If online, start a sync.

**Deleting is "soft":** set `deleted_at = nowIso()` (and `updated_at`), then queue it. Never remove the row, because other devices need to learn it was deleted.

**Deleting a folder:** first move the notes inside it to the top level (`folder_id = null`, queue each one), then soft-delete the folder. That way no note quietly disappears.

### One sync run = push, then pull

Only one sync may run at a time. If one is already running, reuse it.

**Push:**
1. Take a snapshot of every `syncQueue` entry and remove duplicates (same type + id).
2. Load the **current full** item for each from Dexie and send them all in one `POST /sync/push`.
3. If the request fails (network error or non-2xx), **keep the queue**. It'll retry next time.
4. For each `rejected` result that has a `server_item`, overwrite the local copy with it, **unless** the user edited that item again while the push was in flight (a newer queue entry exists that wasn't in the snapshot). In that case keep the local edit queued.
5. Delete only the queue entries that were in the snapshot.

**Pull:**
1. Read `lastSyncedAt` from `meta` (default `1970-01-01T00:00:00+00:00`).
2. `GET /sync/pull?since=...`
3. Upsert every returned note and folder into Dexie, **except** items that still have pending entries in `syncQueue`. Never overwrite an unpushed local edit.
4. Save the response's `synced_at` as the new `lastSyncedAt`.

### When to sync

- When the app starts
- When the browser comes back online (`online` event)
- When the tab becomes visible again or gets focus
- Every 30–60 seconds while online
- Right after a local change (debounce typing so you don't sync on every keystroke)

Show a small sync status indicator: idle / syncing / synced / error.

## 6. Auth in the app

- `/login` has a single password field. On success, store the token response in `localStorage`.
- Wrap `fetch` in an `apiFetch(path, init)` helper that:
  1. Adds `Authorization: Bearer <access_token>`.
  2. On a `401`, calls `/auth/refresh` **once**, saves the new tokens, and retries the request.
  3. If the refresh fails, clears the tokens. The user is sent to `/login` **only if** they aren't already viewing their notes. Their local notes stay readable and editable.
- Only show the login screen when there are no tokens at all.
- Log out clears the tokens. Listen to the `storage` event so logging out in one tab logs out the other tabs too.

## 7. Editor, attachments, search

- **Editor:** CodeMirror with Markdown. Note title + body. Save to Dexie as the user types (debounced, about 500 ms).
- **Preview:** render the Markdown with markdown-it. Make sure raw HTML is disabled or sanitized.
- **Images:** when the user pastes or drops an image:
  1. Insert a placeholder like `![Uploading…]()`.
  2. `POST /attachments/presign-upload`, then `PUT` the file to `upload_url`.
  3. Replace the placeholder with `![](attachment:<attachment_id>)`.
  4. When rendering, turn every `attachment:<id>` image into a real URL via `GET /attachments/<id>/download-url` (cached for about 4 minutes).
  Store the `attachment:<id>` reference in the note, **never** the presigned URL, because it expires.
- **Search:** index title + content of non-deleted local notes with Fuse.js. It's instant and works offline.
- **Layout:** on desktop, three panes: folders/tags sidebar → note list → editor. On mobile, one pane at a time with back navigation.

## 8. Optional: "Share to Yaadi" from your phone

With the PWA installed, it can appear in the phone's share sheet. In the `vite-plugin-pwa` manifest:

```js
share_target: {
  action: '/share-target',
  method: 'GET',
  params: { title: 'title', text: 'text', url: 'url' },
}
```

The `/share-target` route should:
1. Create a note in a folder named `Shared` (create the folder if it doesn't exist) from the shared title, text and URL.
2. If there's a URL, call `GET /links/preview?url=...` (6-second timeout, best-effort) and add the result to the note as a quote:
   ```
   > **Page title**
   > Page description
   ```
3. Sync, then open the note.

## 9. Cloudflare Worker (required)

The backend refuses (`403`) any request that's missing a secret header, so the frontend **must** reach the API through a small Cloudflare Worker. The same Worker can also host the built app.

`worker.js`:

```js
// Serves the built app on the main domain, and proxies everything on
// API_HOST to the Lambda backend with the secret header added.
export default {
  async fetch(request, env) {
    const url = new URL(request.url);
    if (url.hostname !== env.API_HOST) return env.ASSETS.fetch(request);

    const upstream = new Request(env.API_ORIGIN + url.pathname + url.search, request);
    upstream.headers.set('X-Origin-Secret', env.ORIGIN_SECRET);
    // Always overwrite: the backend uses this to lock out password guessers per IP.
    upstream.headers.set('X-Client-IP', request.headers.get('CF-Connecting-IP') ?? '');
    return fetch(upstream);
  },
};
```

`wrangler.jsonc`:

```jsonc
{
  "name": "yaadi-app",
  "compatibility_date": "2026-10-01",
  "main": "worker.js",
  "assets": {
    "directory": "./dist",
    "binding": "ASSETS",
    "not_found_handling": "single-page-application",
    "run_worker_first": true
  },
  "vars": {
    "API_HOST": "api.your-domain.com",
    "API_ORIGIN": "https://<your-function-url>.lambda-url.<region>.on.aws"
  },
  "routes": [
    { "pattern": "your-domain.com", "custom_domain": true },
    { "pattern": "api.your-domain.com", "custom_domain": true }
  ]
}
```

- `API_ORIGIN` is the `FunctionUrl` output from the backend deploy, **without** a trailing slash.
- `ORIGIN_SECRET` is a Worker **secret**, not a var. Set it with `npx wrangler secret put ORIGIN_SECRET` and paste the **exact same value** you stored in AWS (see the backend README). Even an extra newline makes every request return `403`.
- Don't add CORS handling to the Worker. The backend's Lambda Function URL already sends the CORS headers, and the Worker passes them through.
- Deploy with: `npm run build && npx wrangler deploy`

## 10. Build order

Build and test in this order:

1. Login page + `apiFetch` (just confirm login works).
2. Dexie schema + local notes/folders CRUD + editor. The app should be fully usable with **no backend** at this point.
3. The sync engine (section 5). Test it with two browsers: edit in one, see it in the other. Then go offline, edit, come back online.
4. PWA manifest + service worker. Install it and confirm it opens offline.
5. Search.
6. Image attachments.
7. Optional: share target.

## 11. Done when

- [ ] Login works. A wrong password shows an error, and 5 wrong tries show the lockout message.
- [ ] With Wi-Fi off, notes and folders can be created, edited, deleted and searched, and nothing is lost after a reload.
- [ ] After reconnecting, offline changes reach the server and show up on a second device.
- [ ] A note deleted on one device disappears on the other after its next sync.
- [ ] Editing the same note on two devices keeps the newer edit everywhere, with no crash and no stuck queue.
- [ ] Deleting a folder moves its notes to the top level instead of losing them.
- [ ] Pasted images upload, display, and still display after a reload hours later.
- [ ] The app can be installed to the home screen/dock and opens with no connection.
- [ ] Every timestamp the app writes looks like `2026-10-12T09:30:15.123000+00:00`.
